# WGSL / Horizon porting guide

Muon is written so that a port to WGSL (for [Horizon](https://github.com/horizon) or
any Vulkan/WGPU renderer) is mechanical rather than a rewrite. This document is
the contract.

---

## 1. What is already portable

Every file in `shaders/lib/` is pure GLSL 4.00 with no loader-specific tricks
except `lib/uniforms.glsl` (which becomes a WGSL uniform block) and
`lib/buffers.glsl` (which is loader configuration, not code).

Specifically, the code avoids:

* compute shaders, SSBOs, image load/store
* geometry and tessellation shaders
* `gl_FragData`, `gl_FragColor`
* `texture2D`-style legacy functions
* dynamic-length arrays
* bit-field packing macros beyond `&`, `|`, `^`, `<<`, `>>`, `%`
* `discard` outside alpha-tested gbuffer/shadow stages

It also avoids **fixed-function vertex state** everywhere except the four
`*.vsh` shared stages, which use `gl_Vertex`, `gl_Normal`, `gl_Color`,
`gl_MultiTexCoord0/1`, `gl_TextureMatrix[0]`, `gl_ModelViewMatrix` and
`gl_ProjectionMatrix`. Those are exactly the inputs a modern renderer provides
as explicit bindings.

## 2. Stage-by-stage mapping

| GLSL | WGSL |
| --- | --- |
| `vec3`, `ivec2`, `mat3` | `vec3<f32>`, `vec2<i32>`, `mat3x3<f32>` |
| `float(x)`, `uint(x)` | `f32(x)`, `u32(x)` |
| `mix(a, b, t)` | `mix(a, b, t)` (same) |
| `mod(x, y)` | `x % y` for integers; `x - y * floor(x / y)` for floats |
| `fract(x)` | `fract(x)` |
| `inversesqrt(x)` | `inverseSqrt(x)` |
| `texture(s, uv)` | `textureSample(s, samp, uv)` |
| `texelFetch(s, i, 0)` | `textureLoad(s, i, 0)` |
| `textureSize(s, 0)` | `textureDimensions(s)` |
| `dFdx` / `dFdy` | `dpdx` / `dpdy` |
| `#define` switches | `override` constants or pipeline variants |
| `layout(location = N) out` | `struct FragmentOut { @location(0) ... }` |
| `uniform sampler2D` | `@group(0) @binding(n) var t: texture_2d<f32>` + sampler |
| `uniform float` | a member of the uniform struct |

## 3. Uniform block

`lib/uniforms.glsl` maps to one uniform buffer. Group the members exactly as
they are ordered there; that keeps the WGSL and GLSL in lockstep and makes the
Rust side a `#[repr(C)]` struct generated from the same list.

Special cases:

* `sunPosition`, `moonPosition`, `shadowLightPosition`, `upPosition` are **view
  space** in the GLSL pack. In WGSL, keep them scene-space and drop the
  `gbufferModelViewInverse` rotations in `space.glsl` — that is a net win.
* `eyeBrightness`, `eyeBrightnessSmooth` are 0–240 in GLSL; normalise to 0–1 at
  the binding boundary and delete every `/ 240.0`.
* `frameTimeCounter` and `frameCounter` must be provided; the noise and TAA
  code depends on both.

## 4. Texture bindings

| GLSL name | WGSL binding suggestion | Notes |
| --- | --- | --- |
| `gtexture` | `t_albedo` | sRGB sampled as linear, or linearised in shader |
| `normals`, `specular` | `t_normal`, `t_specular` | same atlas UVs |
| `noisetex` | `t_bluenoise` | generated by `tools/generate_noise.py` |
| `depthtex0/1` | `t_depth_opaque`, `t_depth_all` | `depth32float` |
| `shadowtex0/1` | `t_shadow`, `t_shadow_opaque` | comparison sampler optional |
| `colortexN` | `t_buffer_N` | see the buffer table in `ARCHITECTURE.md` |

## 5. Pass graph

The pass order and read/write sets are listed in `docs/ARCHITECTURE.md`. In a
WGSL renderer they become explicit render passes; the only thing to preserve is:

* `colortex5` and `colortex12` are **persistent** (do not clear).
* `colortex9` and `colortex10` **must** clear every frame.
* The translucent buffers use premultiplied alpha with
  `src = ONE`, `dst = ONE_MINUS_SRC_ALPHA`.

## 6. Suggested module layout for Horizon

```
muon/
  math.rs        <- lib/common.glsl
  space.rs       <- lib/space.glsl
  random.rs      <- lib/random.glsl
  noise.rs       <- lib/noise.glsl
  color.rs       <- lib/color.glsl
  brdf.rs        <- lib/brdf.glsl
  materials.rs   <- lib/materials.glsl
  encoding.rs    <- lib/encoding.glsl
  shadow.rs      <- lib/shadow.glsl
  atmosphere.rs  <- lib/atmosphere.glsl
  clouds.rs      <- lib/clouds.glsl
  ao.rs          <- lib/ao.glsl
  ssr.rs         <- lib/ssr.glsl
  volumetrics.rs <- lib/volumetrics.glsl
  water.rs       <- lib/water.glsl
  lighting.rs    <- lib/lighting.glsl
  raytracing.rs  <- lib/pathtracing.glsl
  denoise.rs     <- lib/denoise.glsl
  post.rs        <- lib/post.glsl
```

Each `.rs` file holds a `const MODULE: &str = include_str!("module.wgsl");` and
the WGSL is assembled by prepending the modules in dependency order. Because
the GLSL files are already dependency-ordered by their `#include`s, the same
order works.

## 7. Porting pitfalls

1. **Preprocessor.** Replace `#ifdef` with either `override` pipeline constants
   or separate pipeline variants. The settings that change loop bounds
   (`CLOUDS_CUMULUS_STEPS`, `GTAO_SLICES`, `SHADOW_SAMPLES`, `VL_STEPS`, …)
   are ideal for `override`.
2. **Loops with uniform bounds.** WGSL requires loop bounds to be resolvable at
   compile time *or* uniform; the settings-driven ones are fine, but
   `trace_path`'s `min(RT_MAX_BOUNCES, 6)` must be clamped on the Rust side.
3. **`mat3(m)` casts.** GLSL's matrix-from-matrix construction truncates;
   WGSL needs explicit `mat3x3<f32>(m[0].xyz, m[1].xyz, m[2].xyz)`.
4. **Swizzle assignment.** `c.yz = clamp01(c.yz)` in `hsl_to_rgb` is illegal in
   WGSL; split into components.
5. **Struct returns.** Fine in WGSL, but the GLSL `out` parameters
   (`unpack_gbuffer_0(..., out vec3, out uint)`) become tuple/struct returns.
6. **`gl_FragCoord`.** Use `@builtin(position)`; remember WGSL's `position.y`
   points down in some backends — Horizon already normalises this.
7. **Depth range.** GLSL `[0,1]`; Vulkan/WGPU also `[0,1]`, so
   `screen_to_view_space()` ports unchanged. If the target uses `[-1,1]`, only
   `view_to_screen_space()` and `screen_to_view_space()` need a tweak.
8. **Sampler state.** Shadow sampling relies on nearest filtering; SSR and
   bloom rely on linear clamp. Bind separate samplers per texture rather than
   sharing one.

## 8. Keeping the two in sync

The intended workflow is:

1. Make a change in `shaders/lib/*.glsl`.
2. Run `python tools/validate.py --root .` (the GLSL side stays green).
3. Port the same change into the WGSL module in Horizon.
4. Run Horizon's own validation.

Because the GLSL side is the reference implementation, the WGSL port should be
written *after* the GLSL behaviour is stable. The naming in this repository
(`snake_case` functions, one module per concept) was chosen so that a mechanical
translation produces idiomatic WGSL rather than a transliteration.
